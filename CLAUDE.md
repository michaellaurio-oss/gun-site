## Data model (SQLite)

- **`firearms`** — one row per MODEL (spec catalog). Imperial columns (`*_in`, `*_oz`, `*_lb`) are entered; metric columns (`*_mm`, `*_g`, `*_kg`) are **generated columns** — never insert into them. `category` ∈ handgun / rifle / shotgun / other (other = receivers, build kits). `description` = marketing blurb (model-level). `data_notes` = sourcing notes, conflicts, "placeholder caliber" flags. `source_url` = where specs came from.
- **One spelling per caliber / action** (migration 006, 2026-09-30): `value_aliases (field, alias, canonical)` maps known spellings (".38 Spl" -> ".38 Special"); `canonical_value()` applies it when a firearm is saved, when the form is pre-filled from the CA roster, and in the roster copy. Admin > Firearms > Tidy calibers & actions (`admin/values.php`) merges spellings (updates firearms + remembers the alias) and can forget an alias. 006 cut calibers 77 -> 34 and actions 21 -> 15; left alone as ambiguous: ".22", ".45", "Revolver, double action", plain "Revolver" / "Semi-auto".
- **`listings`** — one row per PHYSICAL gun for sale, `firearm_id` → firearms. Key fields: `stock_number` (unique; optional only while status is draft/coming_soon — enforced by CHECK), `status`, `price_usd`, `condition` (New, Like New, Excellent, Very Good, Good, Fair, Poor), `condition_notes`, `est_round_count`, `finish_color`, `modifications`, `magazines_included`, `original_box`, `included_items`, `description` (per-gun), `additional_comments` (public), `internal_notes` (**private – never render**), `listed_at`, `sold_at`, `sold_price_usd`.
- **California:** `firearms.ca_rostered` (1 = on the current CA DOJ Handgun Roster, 0 = off roster, NULL = not yet checked / long gun) + `ca_roster_checked_on` date + `ca_roster_entry` (the `ca_roster.detail_path` it was matched to). The roster lists specific models, so it lives on the model. Set via Admin > CA roster (see `ca_roster` table). Per the owner: off-roster handguns that are properly registered in CA can be sold USED, by the dealer or via private-party transfer — so used off-roster handguns are listed normally. A NEW handgun off the roster can only be sold to qualifying law enforcement: since 2026-09-30 (Michael) such listings are allowed and shown as **"LEO Sales Only"** (`leo_only()`: new + handgun + `ca_rostered = 0`; NULL/unchecked is not flagged) with a dark-blue badge on cards and compare, a notice on the gun page, and a badge in the admin Listings table.
- **New vs used:** `listings.new_used` ∈ new / used (default used). New guns should use condition "New".
- **Roster triggers removed** (migration 005, 2026-09-30): new off-roster handguns are no longer refused; they are flagged "LEO Sales Only" instead (see California above).
- **Unchecked roster status** (migration 007, code review 2026-09-30): a NEW handgun can't be put on the site (coming soon / available / on hold / pending) while its model's `ca_rostered` is NULL; Draft is fine. A model with new listings on the site can't be reset to unchecked. The public view no longer has `consignment`.
- **Roster matching** (code review): "Exact" (100, the only score "Confirm all" uses) needs the same model name AND the same caliber (`roster_caliber_key()`) AND no colour/finish difference (`roster_finish_words()` on `model_base`); otherwise 90 = "Possible", a person decides.
- **Consignment:** `listings.consignment` (0/1, default 0). No filter (owner's decision). How/whether to show it publicly is not decided yet — ask Michael.
- **Magazine capacity:** wherever factory capacity over 10 is shown (cards, detail facts, spec table), append "(10 round limit in CA)". `listings_public.ca_capacity_note` provides it (NULL when capacity ≤ 10).
- **"Off roster" hover note** (inventory card tag + detail page CA Roster fact): exactly "Not on current CA handgun roster". No further explanation — CA buyers know the rules or will ask the shop.
- **Stock photos** (Michael, 2026-09-30): a NEW listing with no photos of its own shows its firearm model's manufacturer photo, `public/stock-photos/<slug>.jpg` (+ `-sm.jpg`), with a "Stock photo" tag whose hover/focus note is `STOCK_PHOTO_NOTE`. Never on used guns. The file is found by slug (no DB column, so no live-DB change; `stock_rename()` moves it when a slug changes). Admin > Firearms > (a firearm) > Stock photo: Find photo (from the manufacturer page, preview before saving), Upload, Remove; these write straight to the server's `stock-photos/`, and a later deploy only overwrites a slug that also exists locally. Bulk: `php dev/fetch_stock_photos.php [slugs] [--force]` (rules shared in `public/app/stock_photos.php`, sources logged in `dev/stock_photo_sources.csv`), only from manufacturer pages that allowed the spec research; Kimber now returns 403 and is skipped. Photos are manufacturer images: `public/stock-photos/*` is in .gitignore (public repo) but deployed.
- **`listing_photos`** — many per listing: `file_path` (e.g. `photos/U-0001/left.jpg` or a URL), `caption`, `sort_order`, `is_primary`. Photos live as files, not in the DB. Michael will supply high-resolution photos of each actual gun.
- **`listings_public`** (view) — what the website reads: listings with status coming_soon / available / on_hold / pending, joined to key model specs + `model_description` + `primary_photo`. Excludes internal_notes.
